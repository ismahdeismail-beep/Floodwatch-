# ADR-001: Monorepo with npm workspaces + Turborepo

**Status:** Accepted

## Context

FloodWatch AI spans four frontend apps (web, dashboard, admin, mobile), six
shared TypeScript packages, and nine Python microservices. Without shared tooling,
duplication and drift are inevitable: type definitions, UI primitives, ESLint/TS
configs, and dependency versions would diverge across apps.

## Decision

- Use a single Git repository with **npm workspaces** (`packages/*`, `apps/*`).
- Use **Turborepo** (`turbo.json`) to cache and orchestrate `dev`, `build`, `lint`,
  `test`, and `typecheck` across JS workspaces.
- Publish shared code as workspace-internal packages under the `@floodwatch/*` scope
  consumed via `"workspace:*"` dependency specs (no registry publish needed).
- Python services live in `services/*` outside the npm workspace; Docker Compose
  orchestrates the full stack.

## Consequences

- One-command development (`npm run dev`, `docker compose up`) and consistent CI.
- Shared types (`@floodwatch/types`) guarantee a single source of truth across
  web/dashboard/admin/mobile and the API client.
- Mobile (Expo) requires Metro monorepo configuration (provided in
  `apps/mobile/metro.config.js`); `@floodwatch/ui` is intentionally excluded from
  React Native because it is Tailwind/React-DOM based.
- Tooling must be kept compatible across Next.js and Expo (strict TS, shared configs).

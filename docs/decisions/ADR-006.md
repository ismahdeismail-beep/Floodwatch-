# ADR-006: MLflow Model Registry with Deterministic Baseline Serving

**Status:** Accepted

## Context

The AI core must eventually serve production-trained ML models (gradient boosting,
deep learning, climate-AI candidates such as GraphCast/Pangu-Weather/FourCastNet).
During early platform development there is no trained model, yet every downstream
surface (web risk checker, dashboard, mobile, API) needs deterministic,
testable predictions.

## Decision

- Use **MLflow** as the model registry (experiment tracking, versioning, staging
  → production promotion).
- The `ai` service serves whichever model version is marked production in the
  registry; until any model is promoted, it serves a **deterministic baseline**
  (`v0.1.0`): a sigmoid-weighted composite of precipitation, upstream gauge stage,
  soil moisture proxy, and terrain index — designed to be easily replaced.
- Prediction responses include `modelVersion` so consumers can observe which
  model produced the result.

## Consequences

- Every pipeline can run end-to-end from day one without blocking on model
  training; tests are reproducible.
- The baseline provides a benchmark floor: promoted models must beat it on
  precision/recall before going live.
- Consumers must never hard-code assumptions about a specific model version;
  they should trust the returned `modelVersion`/`confidence` fields.
